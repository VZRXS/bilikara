# v0.8.0-preview.3 发布说明草稿

**草稿：待开发包人工测试后确认，尚未发布。** 发布时填写正式包的验证结果和下载链接，不把分支开发包或源码提交当作已经发布的 Preview 3。

Preview 3 延续 Preview 2 的原生 Rust 桌面版，重点是点歌协作、队列与更新可靠性，以及构建和验证链的整理。

## 多人点歌更容易管理

本场用户支持改名、多选、批量排序和删除。名字变化会同步到绑定同一身份的本地 / 公网 Remote，已有歌曲与历史仍保留点歌时的名字。删除后再添加同名用户不会接管旧点歌。

队列继续按用户轮转，顶歌与手动位置保留。恢复默认排序能正确清除单首队列的人工标记；已离开队列的歌曲和过期拖动位置会被拒绝，避免多人操作覆盖。公网 Remote 不再截断长队列 / 历史，传输采用有界分帧与背压。Remote 编号轻点后显示拖动手柄，取消或被新队列打断时不会提交旧排序。

## 点歌与播放

快速点歌新增原生 YouTube 单视频支持，包括常见短链、Shorts 链接和单链接分享文案，沿用同一队列、缓存与播放器。Host 需要可访问 YouTube；正在直播、播放列表、登录 / 付费 / 地区 / DRM 受限内容不在支持范围。YouTube 不加入 Bilibili 曲库或评分，也不会自动生成人声分离伴奏。

修复点歌成功后因控制台记录异常显示失败的问题，并恢复原唱优先选择在点歌与缓存发布中的一致性。观众屏的竖屏 / 超宽视频正确限制在显示区域内，调整大小时保留媒体节点。修复共享导航 SVG 图标引用冲突及带非 ASCII 内容的二维码长度判断。

旧场次歌单仍可在重新启动后选择导出，指定场次不混入更早记录；这项已有功能继续保留。完整操作说明现集中在 [快速说明与常见问题](../quick-start.md)。

## 更新与维护

桌面更新由独立 updater 执行：先确认更新器就绪再关闭应用，保留恢复目录，并报告更新 / 自动重启失败。过期公告在自动和手动查看中都隐藏，不影响仍有效的版本说明。

开发准备、正式构建 / 组装、libav 前置依赖与缓存、固定版 BBDown 准备、解压包验证使用 Rust 工具；已被替代的 Python 生产器和多组验证驱动实际删除，回归检查转入 Rust / Node。桌面运行时退出 Python 已在 Preview 2 完成；这次没有宣称全部 CI / Source 兼容测试退出 Python，也不改变媒体依赖版本、包布局或数据目录。

## 升级前请看

v0.7.2、Preview 1、Preview 2 到本次版本请使用**完整包手动升级**，不要依赖旧版本的应用内更新器，也不要只换可执行文件。Windows Preview 2 在关闭软件后复制完整 `runtime/` 到新安装；更早的旧后端记录需要只读导入，macOS 则保留 App 外的数据目录。步骤见 [升级与数据保留](../upgrading.md)。先备份，确认记录与播放后再清理旧目录。

Android 仍为预览版。Actions 原生构建、签名 / 解压与回归结果和实际设备验收分别记录；人工确认之前不发布 Release，也不上传升级公告。
