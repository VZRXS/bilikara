# bilikara v0.9.0-preview.1

v0.9 Preview 1 introduces a native **GStreamer** playback engine on the Linux
x86_64 desktop and keeps the existing WebView player as **Legacy /
Compatibility Mode** everywhere. It is a preview: the native engine is
qualified only on virtual output, and physical devices remain unverified.

## Highlights

- **Selectable playback engine.** Runtime settings → *Playback engine* offers
  GStreamer and Legacy / Compatibility Mode. The configured preference and
  the engine that is actually running are shown separately, together with any
  fallback reason. On Linux x86_64, GStreamer is the default when the device
  qualifies; elsewhere the engine is shown disabled with its reason.
- **Real native playback.** The engine runs one GStreamer pipeline per
  authorized program inside the desktop shell, with independent video and audio
  files, accurate seeks, audio variants, Signalsmith pitch shift, signed AV
  delay, volume and mute. Frames are composited beneath the page by the shell;
  no video frame crosses JavaScript IPC, and moving between the Host stage and
  the Audience window never creates another decoder. Rust AppState remains the
  only authority for queue, Next, history and playback generations.
- **Deterministic switching and bounded fallback.** Changing the engine during
  playback reloads the current song at its preserved position and play/pause
  state. A fatal GStreamer failure falls back once to Legacy at the same
  position; selecting GStreamer again retries. There is no retry loop and no
  application restart.
- **Cast/native-output handback** restores the local position and play intent
  atomically, so the Host no longer settles through an unintended pause.
- **Pure K device self-test** no longer retains a Remote-staged, unchecked room
  credential when the room is kept for the self-test.
- **Android FFmpeg corresponding source.** The Android libav source kit is now
  a formal release asset listed in `SHA256SUMS` beside the APK.
- **BBDown is deprecated.** Packages no longer bundle, verify or execute
  BBDown. A saved BBDown download source remains visible as unavailable until
  another source is selected.

## Playback engine

| Topic | Behavior |
| --- | --- |
| Preference | Persisted by the desktop shell (`media-engine-v1.json` beside the Host UI preferences). Remote and Audience never change it. |
| Default | GStreamer only where this build qualified it and the runtime probe found every requirement; otherwise Legacy. |
| Switching | Explicit reload of the current claimed program at its logical position, play/pause intent, volume, mute, audio variant, key shift and AV delay. No Next, history entry or queue change is produced; observations from the retired engine are rejected by identity. |
| Fallback | One fallback to Legacy per program after a fatal error, failed load or repeated stall, shown in Settings until GStreamer is selected again. |
| Unavailable reasons | `not-qualified-on-platform`, `runtime-plugins-missing`, `webview-renderer-unsupported`. |
| Rollback | Select **Legacy / Compatibility Mode**. The Legacy path is unchanged from v0.8. |

### Linux runtime requirements

- GStreamer 1.20 or newer with the base, good and libav plugins (for example
  Ubuntu `gstreamer1.0-plugins-base`, `gstreamer1.0-plugins-good`,
  `gstreamer1.0-libav`, `gstreamer1.0-pulseaudio`): software H.264, AAC and FLAC
  decoders and an audio sink are required. GStreamer is not bundled.
- WebKitGTK 4.1 with its default DMA-BUF renderer. If
  `WEBKIT_DISABLE_DMABUF_RENDERER` or `WEBKIT_DISABLE_COMPOSITING_MODE` is set,
  native video cannot be layered under the page and the engine reports
  `webview-renderer-unsupported`; Legacy keeps working.
- PulseAudio or a PulseAudio-compatible server. Hardware video decoders are
  ranked out; software decoding is the supported preview configuration.

## Upgrade notes

- **From v0.8.x on Windows or macOS:** the installed v0.8 updater requires
  `vendor/BBDown` inside an update package, so it cannot install a v0.9 package.
  Install v0.9 manually as described in [upgrading](../upgrading.md).
- **BBDown users:** select Rust Native or DownKyi as the download source. The
  BBDown login file name and `/api/bbdown/*` route names are kept only as
  compatibility contracts.
- **Linux:** the preview is a portable directory without an installer or in-app
  update. Keep `runtime/` beside the executable when replacing it.

## Known issues and limitations

| ID | Area | Status | Details |
| --- | --- | --- | --- |
| K1 | GStreamer qualification | Open | Qualified only on Linux x86_64 virtual output (Xvfb, PulseAudio null sink, CPU decoding). Physical displays and audio devices, HiDPI scaling, multi-monitor, Wayland compositors, device hot-plug, suspend/resume and long sessions are unverified. |
| K2 | Audience window | Open | Native frames can be painted into the Audience window without another decoder, but this path has no end-to-end virtual-output acceptance yet. |
| K3 | Audio servers | Mitigated | libpulse 15.99–16.x reports a stream that starts corked as having played since its creation (fixed in PulseAudio 17). The engine opens its PulseAudio stream only at a program's first Play. PipeWire's PulseAudio server was not tested. |
| K4 | Codecs | Open | Only H.264, AAC and FLAC software decoders are probed. A cached program in another codec needs the matching GStreamer decoder; otherwise that program falls back to Legacy. |
| K5 | Continuous playback | Open | Each program builds its own pipeline at the boundary (no gapless preloading). The Host's countdown keeps its intentional 500 ms overlay fades before and after the configured interval. |
| K6 | Network output | By design | While a DLNA/Pure K receiver owns playback, the Host uses the Legacy preview path. |
| K7 | DLNA / Pure K receivers | Unverified | Physical receiver compatibility, including the reported Pure K black screen around 0:01, is unverified; only simulated receivers were tested. No hardware qualification flag is set. |
| K8 | Android native media | Unverified | NDK-built libav/Signalsmith companions, ABI negotiation, lifecycle and recovery were not re-verified on devices for this preview. |
| K9 | Other platforms | Not included | Windows, macOS, Android and iOS keep Legacy only and were not packaged for this preview delivery. |
| K10 | v0.8 updater | Open | In-app update from v0.8.x to a package without BBDown fails; install manually. |
| K11 | BBDown | Deprecated | BBDown is no longer packaged or executed by native builds. The Python source Host keeps its frozen BBDown compatibility surface for development only. |
| K12 | Audio-First research route | Retired | The Round A Audio-First harness remains under `research/` and test tooling; no shipped Host, shell, Runtime or package code references it. |

## Verification

Run on Linux with CPU-only settings (`CUDA_VISIBLE_DEVICES=` and software GL).
The private PulseAudio server must provide a null sink, and nothing here
qualifies physical hardware.

```sh
# Engine on real GStreamer and a private PulseAudio server
BILIKARA_TEST_GSTREAMER_ENGINE=1 BILIKARA_TEST_PULSE_SERVER=unix:/path/to/native \
  cargo test --manifest-path media-engine/Cargo.toml --locked --test live -- --ignored --test-threads=1

# Assembled Linux shell on Xvfb (Xvfb, openbox, xdotool, scrot, ffmpeg, parec)
BILIKARA_TEST_GSTREAMER_DESKTOP=1 BILIKARA_TEST_TAURI_EXE=/absolute/dist/bilikara/bilikara-desktop \
  BILIKARA_TEST_PULSE_SERVER=unix:/path/to/native npm run test:native-gstreamer-desktop
```

The desktop acceptance plays two synthetic songs whose every second has its own
colour and tone. It checks picture and sound positions, the start after the
Host's countdown, a Remote seek, exactly one drained EOS, the automatic advance,
the transition timing and a clean window-manager exit, and that no GPU device
is opened.
