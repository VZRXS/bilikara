# 快速说明与常见问题

适用于桌面 Host 与它的本地 / 公网 Remote。手机 Remote 是控制器，在浏览器中打开即可，无需安装 Host。下载与启动见 [README](../README.md)。

## 第一次组织点歌

1. 解压完整桌面包，打开桌面启动器。在「本场用户」添加参与者，按需要拖动调整轮转顺序。
2. 选择点歌人，粘贴 Bilibili 链接、BV / av 号或 YouTube 单视频链接。普通点歌按用户轮转；缓存完成后播放。
3. 在右上角「手机点歌」扫码。局域网手机与 Host 连接同一网络；公网 Remote 需要电脑创建房间，再输入房间信息和密码。
4. 先试一首歌，检查音响、原唱 / 伴奏、音画延迟和音量，再开始正式使用。音轨来自视频已有分 P / 轨道，不是自动人声消除。

可选的[自动音量实验](automatic-volume.md)默认关闭：在 Host 点击播放音量百分比，启用后等待分析，再明确用当前歌曲和舒适音量设为基准。普通 Remote 只能查看状态和手动调节本曲。

电脑关闭后手机不能独立播放；公网入口同样依赖运行中的 Host。

公网长列表可能只显示部分内容，届时会提示显示条数；搜索结果可继续翻页，完整待播列表、历史可在 Host 或本地 Remote 查看、编辑，来源批量管理与排序在 Host 操作。电脑上的数据不会被截断。

在 Host 来源页，普通卡片点击进入来源；点击底部多选按钮后，轻点卡片或 checkbox 选择，从 checkbox 以外的卡片区域拖动排序，或拖入垃圾桶后确认移除。手机也可长按卡片进入多选，再点多选按钮退出；没有独立的排序按钮。拉取期间可编辑已保存的来源，尚未保存的排队占位卡不能编辑；拉取完成的自动刷新等待手势结束，真正的来源成员／排序变化仍会取消旧拖动或确认。切换功能页或来源标签退出多选，翻页保留选择。移除不会删除 B 站收藏夹、已点歌曲或已下载媒体。

## 切换 HiRes 或清晰度时，缓存会怎样变化？

HiRes 控制同一分 P 的音频下载规格，不改变分 P 或原唱／伴奏选择。在 Rust Native 下载器中，开启后有可用 HiRes 流时优先选它，没有则回退可用音频；它不是播放端的音效开关。

HiRes 和清晰度采用相同的生效时机：保存设置后，新建下载任务使用新规格；正在下载或已经排队的任务保留创建时的规格，已完成的缓存不会自动重下。系统会预缓存后续歌曲，因此「下次下载生效」不保证「下一首播放就生效」。需要让已缓存的歌曲使用新设置时，可明确执行重新缓存；失败任务也需明确重试，不会因调整画质或 HiRes 而无限重新下载。

切换下载器仍立即替换当前缓存窗口的任务；播放器兼容性变化、缓存文件被清空或歌曲重新进入缓存窗口，也可能需要新任务。旧请求先取消并关闭连接，再开始新任务，不会同时下载同一首歌的两代缓存。原生 HTTP 传输支持取消正在等待响应头、正文和分段的请求，不必等完整请求超时。自动替换时已经可读的缓存保留到替换完成；明确强制重新缓存会使用既有清理流程。

实际视频规格还取决于播放器上报的 AVC 能力与来源提供的流，音频规格取决于来源是否提供 HiRes。诊断报告 Download Policy 中的 `avc_quality_cap` 是兼容字段，目前等于用户所选的 `video_quality`，不能单凭该字段判断设备解码上限。解析、网络请求、媒体校验失败仍会显示其状态；缓存设置更新不等于播放端已即时切换规格。

## 如何使用播放抽屉与进度条？

Remote 播放抽屉既可点击底部播放栏展开、点击顶部横条或外部遮罩收起，也可在顶栏、底板和普通按钮上开始滑动。按钮上的轻点与小幅晃动仍按原操作执行；明确的纵向拖动接管手势后，松手不会误触按钮。输入框、进度／音量滑条和下拉选择保留自己的操作。矮屏出现滚动条时，内容区的整次手势优先滚动，不在滚到顶端后突然改成收起抽屉，顶栏仍可滑动收起。进度条第一次点按只显示拖拽球，保持当前播放位置；第二次点按或拖动才调整进度。离开进度条后会恢复隐藏，键盘方向键仍可直接定位。

## 如何重唱当前歌曲？

桌面 Host 控制台始终显示重唱、切歌两个独立圆形按钮，窄窗口也保留。直接点击重唱即可从头播放当前歌曲。

在 Remote 的播放面板或手机 Host 播放控制中，竖屏短按「切歌」仍然切歌，长按约半秒会向左展开横向胶囊：左侧重唱，右侧切歌保留原位。可以松手后点重唱，也可以保持按住，向左拖到重唱按钮，松手后从头播放；暂停中的歌曲也会开始播放。保持在切歌处松手不会执行操作。任意新的点按都会收起胶囊，点重唱或切歌会同时执行对应操作；Escape 也可取消。鼠标可右键切歌键展开；键盘聚焦切歌键，按左方向键展开，再用 Enter 执行。

横屏直接显示重唱、切歌两个独立圆形按钮，不加外层胶囊。播放面板有左右两栏时，左侧高度足够就让进度条独占一行，按钮放在下一行；右侧设置区需要滚动不影响这个判断。高度不足时仍使用紧凑布局。竖屏弹出菜单的胶囊两端为完整半圆，不增加布局行。两枚按钮均为 44px，重唱箭头与「后退 15 秒」一致。重唱不弹出确认窗口，后退 15 秒的操作保持不变。

观众画面的重唱提示使用独立图标和「重唱」文字，与进度定位、播放／暂停共用同一类短暂操作提示，不叠加重复卡片。双屏输出也显示新点歌提示，包括空闲时的第一首；初次加载旧队列或继续上一场不会当作新点歌。

重唱保留当前点歌人、音轨、音调、音量、延迟、评分和待播队列，不重新点歌或下载。只有当前播放器支持定位且歌曲可播放时可用；展开后切歌会关闭旧入口。请求失败或结果未确认时不会自动重试，请先检查播放状态。

缓存或播放器尚未就绪时，仍可长按切歌展开胶囊，重唱键保持灰色；点按或滑入后松手均不会执行。普通状态刷新不会仅因重唱不可用而收起菜单。

Remote 和手机 Host 首次进入可操作的竖屏播放控制时，胶囊会自动展开、收起一次，提示切歌旁还有重唱入口。这个提示不会播放、切歌或抢走焦点；开始操作就立即让位。横屏不会消耗这次提示，桌面 Host 已常显重唱，无需自动演示。Remote 在当前浏览器站点记录是否看过，清除站点数据后会再次提示；原生 Host 使用设备本地记录，不因本地服务端口变化而重复。

播放控制区的后退、播放/暂停、前进、重唱、切歌圆形图标，长按约半秒会显示与 i 说明相同的气泡。保持按住滑到其他圆形按钮，会切换为该按钮的说明；松手或移开后收起气泡。普通按钮长按不执行播放操作，短按仍按原方式执行。胶囊收起时切歌的说明为「切歌；向左滑动可重唱」；从切歌滑入重唱只是按住该键，松手才执行，移开或取消则不执行。首次自动提示保留展开动画，操作说明只在实际长按时显示。

## Remote 播放面板如何滑动展开、收起？

点击和拖动使用同一种播放栏变宽、变高的过渡，顶部常显横条随面板内容一起出现。触屏从播放栏上划展开，展开后可在顶栏、底板或普通按钮上向下拖动收起；控件与滚动的优先级见上文。松手后根据位置与最近的速度决定完成或弹回。短距离慢拖会弹回，快速甩动也可完成展开、收起；反向拖动会重新判断。取消触摸、切歌或旋转窗口会结束旧手势，不执行播放操作。顶部缓存状态、播放时长与点歌人不会因长按进入文字选择；需要复制长标题时仍可打开完整文字面板。

## 局域网连接不上怎么办？

先检查 Host 是否仍在运行、防火墙是否允许 bilikara，以及 VPN / 多网卡是否让手机使用了错误的电脑地址。**连接同一个 Wi-Fi 不一定能互相访问**：路由器的「AP / 客户端隔离」或访客网络可能禁止设备互访。可换到允许设备互访的网络，或在自己管理的路由器上调整隔离设置。

公网入口也要建立 Host 与手机之间的 WebRTC 连接。在 Host 本机打开公网链接成功，不能证明其他设备可达；网页 / 房间服务可达也不等于控制通道可达。分阶段排查与管理员可选中继见 [公网 Remote 网络说明](internet-remote-network.md)。

无法调整路由器时，可以尝试自己建立热点：

- **Windows 开热点**：在「设置 → 网络和 Internet → 移动热点」中选择现有有线或 Wi-Fi 连接，再让点歌手机连接电脑的热点。能否一边连接现有 Wi-Fi、一边开热点，取决于无线网卡与驱动。
- **Mac 开热点**：先通过有线网络上网（需要时接 USB 网卡），再在「系统设置 → 通用 → 共享 → 互联网共享」中选择有线网络为来源、Wi-Fi 为共享方式，让点歌手机连接这个热点。这里只推荐「有线网络 → Wi-Fi 热点」；如果只有现有 Wi-Fi 连接，可改用手机热点。
- **手机开热点**：让 Host 电脑和其他点歌手机接入同一个手机热点。iPhone 个人热点使用蜂窝数据，不能把已连接的 Wi-Fi 再开成热点，下载视频会消耗移动流量；其他手机是否支持 Wi-Fi 中转，以机型为准。

切换网络后，重新打开「手机点歌」，使用电脑在热点网络中的地址连接。防火墙仍需放行，热点也须允许设备互访。系统操作可参考 [Windows 移动热点](https://support.microsoft.com/zh-cn/windows/experience/connectivity-networking/use-your-windows-device-as-a-mobile-hotspot)、[Mac 互联网共享](https://support.apple.com/zh-cn/guide/mac-help/mchlp1540/mac) 与 [iPhone 个人热点](https://support.apple.com/zh-cn/111785)。

## 重新打开会继续上一场吗？

检测到上一场时会显示选择提示。**点击「继续上一场」保留原用户、队列与本场歌单；关闭提示或等待 10 秒倒计时结束会开新一场。** 鼠标悬停、键盘焦点位于提示内或页面隐藏会暂停倒计时。选择提交失败时会保留提示，需手动重试。

提示显示期间，运行设置和本地手机访问二维码仍会正常显示；上一场的播放与用户、队列修改需先完成选择。打开运行设置不会在选择前自动发起哔哩哔哩登录。

开新一场保留历史记录、归档歌单、登录和设置。不要把「清空点歌列表」「清空历史」或重置数据当作正常结束一场的方法；它们是不同操作。

## 本场用户、手机身份和排序

- 整场名单由 Host 管理，最多 32 个用户。多选可批量拖动、删除；改名模式与多选模式分别操作。
- Remote 不开放整场名单的修改，避免参与者误操作；可以选择已有身份、添加自己的身份或修改自己的名字。
- 绑定同一身份的设备会同步改名。已有队列、历史和导出的名字仍是点歌时的记录，之后点歌才使用新名字。
- 删除用户不会删除其已点歌曲，但会解除手机身份。再添加相同名字是一个新身份，不自动接管旧歌曲。

普通点歌按本场用户顺序轮转，跳过没有等待歌曲的用户。**顶歌**放到等待队列第一位，**立即播放**会结束并替换当前节目。拖动的歌曲保留人工位置；「重新排序」清除顶歌 / 人工位置并恢复轮转，但保留每个用户歌曲在当前队列中的相对顺序。

Remote 轻点编号可查看提示；编号切换成手柄时也可拖动。松手后提交，取消手势不会排序。其他人同时改动队列时可能需要重新拖动，避免用过期位置覆盖他们的操作。

## 来源、本地曲库和共享曲库有什么区别？

| 入口 | 数据从哪里来 | 如何使用 |
| --- | --- | --- |
| 来源 | 指定 UID 的稿件、收藏夹等元数据 | 添加 UID，选择来源并拉取；需要访问权限的内容须使用有权限的 Bilibili 登录 |
| 搜索 → 本地曲库 | 本机已拉取的来源元数据 | 拉取后检索已收录歌曲，与来源页共用数据 |
| 试试运气 | 配置的本地来源池 | 从收录条目随机选歌；可以配置来源与排除条件 |
| 共享曲库、类别、作品名、歌手 | 在线共享数据库 | 直接搜索 / 浏览，依赖共享服务可用性，不要求先拉取自己的 UID |

来源拉取收录的是**元数据**，并不提前下载整份收藏夹或 UP 主的所有视频。真正点歌后才按缓存窗口准备媒体。拉取任务排队进行，可继续添加来源；失败可重试。首次收录或刷新前，本地搜索和随机池可能没有可用条目。

可见的稿件 / 收藏夹取决于平台公开范围和账号权限。共享曲库的数据与用户自己的来源数据不是同一份；本机拉取不等于自动上传全部收藏夹。

桌面与 Android Host 使用底部常驻的多选和垃圾桶工具；Android 也可长按来源卡片进入多选。原数量位置的 checkbox 负责选择，多选时从卡片其余区域拖动所选组，调整展示顺序或拖入垃圾桶后确认移除。再次点多选图标即退出，没有独立「完成」按钮；也可用 Alt＋上下方向键调整顺序。具体操作、失败处理和 Remote 的 UI／接口边界见 [管理本地来源](source-management.md)。

## YouTube 可以怎样点歌？

快速点歌支持 watch、youtu.be、Shorts、embed 等单视频链接，也可粘贴包含一条视频链接的分享文案。多个不同视频、只有播放列表的链接和正在直播的内容不能作为一次点歌。Host 需要能访问 YouTube 及其媒体服务器。**当前暂不支持 YouTube 账号登录**，需要登录或付费权限的内容可能无法播放；地区或 DRM 限制也不会被绕过。

YouTube 使用现有队列与播放器，但不参与 Bilibili 收藏夹、试试运气、共享曲库收录或视频评分。单条音轨不代表有伴奏；当前兼容画面上限为 1080p，具体画质依可用轨道与设置而定。

## 双屏为什么没有可选屏幕？

先连接电视 / 投影仪，再在**操作系统显示设置中选择「扩展」**。Windows 可按 `Win + P` →「扩展」；macOS 关闭镜像并选择扩展显示。复制 / 镜像模式不是两个独立操作面，单纯连接同一 Wi-Fi 也不会产生观众屏。

在 Host 右上角「双屏显示」刷新并选择观众屏，点击「识别屏幕」确认编号，再启用。电脑保留控制界面，观众屏显示播放画面；声音输出仍需在系统 / 音响上检查。单屏全屏与双屏是不同入口。

## 如何导出结束后的指定场次？

Host 与完成身份登记的**本地 Remote**都可在「历史记录 → 导出」选择范围；**公网 Remote 不支持歌单导出**：

- **本场记录**：当前场次的已播放记录。
- **归档场次**：按日期选择指定场次；开新一场、关闭软件并重新打开后仍可选择。
- **历史记录**：累计点歌历史，与某一场的已播放歌单不同。

选择一个归档场次只读取该场，CSV 和图片都不会拼入更早场次或累计历史。可先导出 CSV 核对范围；图片单页为 PNG，多页为 ZIP。历史里有歌曲，不意味着该歌曲已在指定场次播放；尚未实际开始播放的点歌不一定进入已播放歌单。

## 登录、下载器与维护

桌面默认使用内置 Rust Native；BBDown 与 DownKyi / aria2c 是显式备选。Bilibili 会员画质和受限内容依赖当前账号权限；切换下载器不会赋予新的访问权限。运行设置可以扫码登录 Bilibili，过期二维码会刷新；这个登录不适用于 YouTube。

媒体按缓存窗口准备；失败的歌曲可以重试。退出会清理播放缓存，歌单和播放器设置保留。不要在软件运行时复制、合并或删除数据目录。

Rust Native 日志中的 `HTTP range response body failed` 表示 HTTP 分段响应的正文读取失败；它与登录失败、HTTP 状态码拒绝、分段长度不符和本地写盘失败是不同错误。单条日志不能进一步区分超时、连接中断或 CDN 原因。原生下载按轨道最多尝试 10 次，两次尝试间等待 3 秒；失败轨道会重新获取媒体地址并重下该次轨道，已完成的其他轨道无需重下。短暂失败不等于整首缓存失败；判断重试原因时请保留重试前后的诊断包，不要仅凭一次连通性探测或清晰度设置推断。

Windows 默认数据在程序旁的 `runtime/data/`，完整便携数据还包括 `runtime/` 下的其他内容；macOS 位于 `~/Library/Application Support/bilikara/`。备份时保留整份数据，不要只复制媒体缓存。登录凭据和完整数据备份不要公开分享。启动 / 播放问题可先导出诊断包，并说明系统、版本和操作步骤。
