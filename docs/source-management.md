# 管理本地来源

在 Host 的「点歌 → 来源」管理 UP 主与收藏夹。两类列表独立；桌面与 Android Host 使用同一套操作。查看某个来源的歌曲时，管理工具隐藏；返回来源列表后恢复。卡片正文仍用于进入来源，正文区域仍可正常触屏滚动。

Host 与 Remote 复用同一条来源操作行：输入框、添加和手动更新并排；收藏夹使用输入框和获取按钮。窄窗口只压缩输入框宽度，不改成三行。输入框按 Enter 仍执行添加／获取，手动更新是独立按钮，不提交输入框。

普通模式单击进入来源。排序并入多选，不再有独立的排序按钮；多选时轻点卡片任意位置切换选择，从 checkbox 以外的卡片区域拖动已选组。checkbox 区域显示点击手指，其他位置显示抓取手掌。保留 Alt＋上下方向键。相邻卡片的插入竖条位于间隙中央，首列、末列也可看到；拖向相邻行时，进入该行一段距离后才切换目标，避免边界抖动。排序成功只通过 toast 提示，不保留右下角的排序目标说明。

## 多选与移除

两端点击底部与「本场用户」一致的多选图标，逐个选择卡片，或使用「全选」。移动端的全选作用于当前页；当前页已全部选择时，同一按钮变为「取消全选」，清除全部选择。再点多选图标退出多选。

Android Host 长按卡片进入多选，并立即选中该卡片；之后轻点卡片或 checkbox 切换选择。卡片及其标题、头像、checkbox 区域禁止文字选择和系统长按菜单，避免手势同时触发选字；普通模式的卡片正文仍可滚动。滑动、手势取消、失焦、页面切换或来源成员／排序变更会取消尚未完成的长按，轻点仍进入来源。

两端的多选状态都把卡片原来「x 首」／数量的位置替换成原生 checkbox，标题、头像和卡片尺寸保持原样。退出后恢复数量。checkbox 支持键盘空格键，只负责选择，不启动拖动。多选模式下，卡片其余区域可立即拖动；普通模式仍可滚动。选中描边使用卡片内部的 1px 边框，与「本场用户」一致，不向外扩张。

桌面与 Android Host 都复用「本场用户」的底部常驻工具行，位于列表滚动区之外，没有弹窗、额外底色、模糊或阴影。多选／完成和垃圾桶并排常显，圆心对齐；进入多选时在其左侧显示全选与已选数量。工具行固定为 52px，容纳共享的垃圾桶命中区；进出多选不改变列表视口、卡片尺寸或按钮位置，也不增加临时滚动余量。垃圾桶在没有有效选择时变淡，始终不可点按。多选图标以选中状态表示正在多选；再次点按即「完成」，退出并清空选择，不执行删除。

桌面 Host 来源列表恢复连续滚动，完整列出本地来源，不创建分页器。Android Host 的分页器属于面板边框，常驻工具行下方，位于滚动区之外。每页数量依据扣除工具行后的实际列表视口、卡片高度与间距按整行计算，最多 48 项；普通模式尽量整页放下。高度不足以显示一行时，列表内部仍可滚动，工具行与分页器不随之移动。窗口大小、字体或语言变化会重新测量；调整容量时保留原来可见条目所在的位置和跨页选择，不重新提交排序／删除。浏览来源详情时隐藏来源工具行和分页器，返回后恢复。Remote 保留网页滚动与每页最多 12 项，不套用 Host 的固定边框。

来源列表与常驻底栏之间保留与「本场用户」一致的 8px 间隔。移动端按钮行和分页器组成一个边框内的底栏；分页复用 Remote 的 44px 轨道、居中的 32px 输入框和 4px 面板底部间距，不再套上额外的分页上下内边距。管理行仍保留 52px 垃圾桶命中区；其下方的 4px 绘制余量加上两行间 4px 间隔，形成 8px 控件间距。桌面只有管理行，最下方使用与「本场用户」一致的面板纵向内边距。列表上下各保留 2px 绘制空间，避免旧列表内边距挤掉完整的一行。有更多可用高度时立即增加整行，不固定为三行或五行，也不缩小共享的 72px 卡片。常驻工具行会占用一定高度，容量取决于剩余的实际内容视口；Android 系统栏、字体和横竖屏都会影响可用空间。放不下下一完整行时剩余的列表空间不是额外 margin。

移动端主要适配下限是 **360px CSS 宽度**；320px 下也保留同一行操作、完整卡片和可用分页器，UID 输入框会更窄。640～1000px 可用高度按完整行增加容量，中／英／日界面使用相同的卡片与控件尺寸。日常竖屏展示优先检查 360×800、375×812 和较短的 375×667；1000px 只是高视口的边界检查，不代表所有手机的实际形态。这里的高度是 WebView 内容窗口，不能把 Android 状态栏、系统导航栏或键盘占用算进列表空间。进入或退出多选均保留原页容量，内容确实溢出时仍可滚动。

与「本场用户」共用的是滚动区外的常驻工具行、多选与垃圾桶图标及其按下状态、原生 16px checkbox、44px 圆形工具和 52px 垃圾桶命中区。删除流程仍不同：「本场用户」支持点击删除，来源仅支持从卡片正文拖入后确认。桌面来源使用连续滚动，Android 来源保留分页。

选择可以跨越同一列表的多个页面，显示所选**总数**，不是当前页的数量。切换来源类型、筛选条件或离开来源列表会清空选择；已被其他客户端移除的来源会从选择中剔除。

垃圾桶复用「本场用户」的淡色危险操作底色与图标，**不可点按**。从已选项的卡片正文拖入垃圾桶，可以移除全部已选来源；从未选项拖动会先选中该项。进入固定的垃圾桶范围时标志变为实心，松手才在垃圾桶左上方显示确认框，并限制在窗口内；文字分两段，列出来源类型、总数和最多三个名称，再说明仅影响本机来源列表及曲库元数据，不影响 B 站、共享曲库、已点歌曲和已下载媒体。拖动时半透明卡片跟随指针，原位的选中组也变淡。拖到外面、取消手势、失焦、尺寸／页面／来源版本变化，都不会触发删除。取消、Escape 或关闭确认框都不会发送删除。确认一次提交一个批次，每批最多 128 个同类来源。提交期间不能重复操作；被拒绝后保留仍然存在的选择，重新读取实际列表，需用户明确重试。删除入口需要鼠标或触屏拖动；键盘仍可选择与退出多选。

**移除只修改本机来源成员和关联曲库元数据。** 它不会取消 B 站关注、删除 B 站收藏夹、改动共享曲库、删除已下载媒体，或修改已点歌曲、播放队列和历史。同一个 BV 出现在其他来源时，其他来源的记录仍保留。移除 UP 主也不会移除另外导入的该 UP 主收藏夹。故意清空的默认来源不会在重启后自动补回。

普通来源拉取或更新进行中，仍可选择、排序和移除；提交继续验证来源版本，避免覆盖期间发生的成员变化。移除不会取消拉取任务。仓库重置、损坏数据或编辑请求提交期间仍暂停编辑。

## 展示顺序

桌面与手机 Host 都在多选状态下从卡片正文拖动排序，checkbox 区域不能启动拖动，卡片内不增加序号或独立手柄。拖动未选项会先将它加入所选组；组内相对顺序沿用保存的展示顺序。一次最多移动 128 项，由 Rust 仓库验证全部 ID、锚点和当前版本后原子写入展示顺序，不会逐项提交而留下半组。也可聚焦目标卡片后按 Alt＋上下方向键；多选时移动所选组。

松手即保存。Escape、无效落点、手势取消、窗口失焦或尺寸变化、页面切换，以及期间收到另一项来源成员／排序变更，都会取消拖动，不保存旧位置。被拒绝的排序恢复实际保存的顺序，需重新操作。分页移动使用全局来源 ID 与锚点，保留不可见条目，不把当前页当作完整列表。

顺序保存在数据目录的小型 `gatcha_source_order.json` 中，UP 主和「所属 UID＋收藏夹 ID」各有独立顺序。没有自定义记录时沿用原来的默认排列；单纯读取不会创建该文件。新增来源追加在现有展示条目之后，刷新内容、计数和时间不覆盖顺序；重新打开 Host 和连接 Remote 后仍采用保存的顺序。

这个偏好**只改变来源卡片展示**。配置中的扫描顺序、手动任务 FIFO、搜索去重、抽取权重、排除条件、下载优先级和点歌队列都不随之改变。排序不重写歌曲缓存。名单不完整、元数据损坏或来自不支持的版本时暂停编辑，保留原文件；仍可查看能够读取的内容。

## 保存失败与清理

一次批量移除先验证全部目标和当前来源版本，然后在现有排他租约内提交成员配置，接着清理缓存和展示顺序。各文件分别原子替换，**不是跨文件事务**。

验证失败或成员配置提交失败时，不会移除来源。成员配置已经提交而后续清理失败时，会提示「来源已移除，部分本地元数据清理未完成」，并按实际成员刷新列表；残留缓存或排序记录不会让已删除来源重新出现。修复数据目录的权限／存储问题后，可以点击「重试清理」。这只整理之前删除的 ID，不重复原批次的删除；如果来源已重新添加，清理会被拒绝，防止误删新成员。旧单个移除接口也可以显式重试清理，需满足它原有的授权。

拉取中或等待拉取的收藏夹也可以进入详情；尚无本地条目时显示相应拉取状态，保留队列提供的收藏夹名称。已拉取的 UP 主和收藏夹详情都只滚动稿件列表，返回和搜索控件保持固定。

底部操作使用与本场用户一致的 tooltip。切换功能页或 UP 主／收藏夹标签会退出多选；列表翻页仍保留所选项。拉取完成的自动刷新会等待当前按住／拖动结束，再合并刷新；其他客户端真正改变来源成员或顺序时，原有版本冲突保护仍生效。

## Remote 的边界

本地与公网 Remote 在本次版本都只提供来源浏览界面：不加载编辑器，没有多选、垃圾桶、排序手柄或长按编辑。它们仍可按既有权限添加 UID、获取收藏夹、设置随机池和点歌，并显示 Host 保存的顺序。其他授权客户端增删来源后，列表会更新；正在查看的来源被删除时返回来源列表，不重建播放器。

这是 **UI 范围限制**。原有 `/api/gatcha/source/remove`、FFI `remove_source` 和公网协议 `gatcha.source_remove` 保留原授权规则；旧版或自定义的已授权 Remote 仍可调用单个移除。新的批量／排序／清理入口 `/api/gatcha/sources/edit` 不增加公网协议命令；原生 Host 要求服务端验证 Host 的引导能力。保留的 source Host 使用它现有的本机客户端边界，Python 只转发到同一个 Rust 仓库规则。

## 本地验证

`node --test tests/source_removal_browser.test.mjs` 是现有 `npm run test:host-experience` 的一部分，使用当前原生 Host、共享 Android Host 夹具和已安装的固定版本 Playwright 浏览器。数据和账户均为合成夹具。它包含批量请求、持久化排序、桌面／触屏交互、LAN Remote，以及通过真实 WebRTC 的本地公网模式；信令复用 `local_signaling_fixture.mjs` 的非转发契约夹具，不执行部署中的 Worker。

前端契约通过 `npm run test:frontend`，静态 Remote 同步契约通过 `npm run test:remote-sync` 检查；Rust 来源仓库测试覆盖损坏输入、版本冲突、成员提交前失败和提交后清理失败。原生来源测试验证真实拉取期间仍可编辑，以及批量排序的原子性和版本冲突。

Linux 上可额外用 `xvfb-run -a env BILIKARA_SOURCE_TEST_HEADED=1 node --test --test-name-pattern='mobile Host fits 360px' tests/source_removal_browser.test.mjs` 验证会占宽度的真实 Chromium 滚动条；需要已安装 Xvfb、xauth 和固定版本浏览器，缺失时命令失败。普通浏览器检查仍使用无界面模式，不启动 Android 模拟器。设备验收要使用实际 APK、真实系统触摸和原生屏幕截图，避免把单次匹配的 DOM 数量当作稳定容量。

需要严格零外部流量时，在一次性 Linux 用户／网络命名空间中运行这些集成测试：仅启用回环与无外部连线的测试 dummy 接口，允许回环出口、丢弃其余 IPv4／IPv6 出口和转发。Chromium 的接口发现需要路由，因此测试默认路由指向这个隔离的 dummy 接口；它没有外部连线，且防火墙禁止其出口。浏览器资源只允许测试 HTTP 服务；移除夹具中的公共 STUN，信令与 API 都指向本地服务。用一个 TEST-NET UDP 探针验证丢弃计数，并记录防火墙计数、接口／路由及夹具请求量。不能只依靠浏览器拦截来约束 WebRTC。网络规则随命名空间销毁，不改工作站防火墙。

共享 Android Host 的 Linux 进程加触屏浏览器能验证共享界面与服务，不能代替 Android 设备、Windows／macOS 原生窗口或发布包验收。上述本地测试不涉及真实 Bilibili 账户、共享数据库、生产 Worker、付费 TURN、部署或静态资产同步。
