# 升级说明

「设置 → 应用更新」默认在每次启动后检查一次正式版；开启「预览版」后包含预览版本。首次启动会先准备本地数据并加载更新设置，再在 Host 的首次有效状态到达后检查。只检查，不会自动下载或安装。

原生桌面端与 Android 会保留「自动检查更新」「预览版」两个选择，退出、重新启动或本地服务端口改变都不会恢复默认。桌面端保存在窗口设置旁的 `update-preferences-v1.json`；Android 保存在应用私有设置。首次使用此存储时，会接收当前网页来源仍可读取的旧设置；旧版其他随机端口中的设置无法自动找回。清除应用本地设置会恢复默认。通过普通浏览器打开 Host 时，选择仍按浏览器来源保存。

启动时若已有更新操作，自动检查会等待它结束，再补查所选频道一次。网络失败不持续重试，可点击「检查更新」重试或下次启动再检查。无法读取或保存本地设置时会提示错误，本次暂停自动检查，不会覆盖损坏的设置文件。

开发验证：`npm run test:frontend` 包含首次启动、后续启动、频道选择与忙碌补查的快速回归；`npm run test:app-updates` 另用 Linux Chromium、实际 Rust Host 和实际设置文件读写验证完整重启与端口变化。更新服务响应和原生调用入口使用本地契约夹具，安装接口被禁止；测试环境应仅允许本地出口。它不代表 Windows/macOS/Android 原生 WebView 已实机通过。

从 **v0.8.0-preview.2 及更早版本** 升级，请下载完整包；这次过渡不使用旧版本的软件内更新。

1. 关闭旧软件，备份数据。
2. 从 [Releases](https://github.com/VZRXS/bilikara/releases) 下载对应系统与架构的完整包，解压到新文件夹。

**从 Preview 2 升级：**

- **Windows**：把旧版整个 `runtime` 文件夹复制到新版，与 `bilikara-desktop.exe` 放在同一级，再打开新程序。
- **macOS**：替换完整的 `bilikara-desktop.app`，保留 `~/Library/Application Support/bilikara/`，再打开新程序。这个文件夹包含歌单和设置，不只是 WebView 缓存。

**从 Preview 1 及更早版本升级：**

关闭旧软件，首次打开新版时会检查已知的旧数据位置；检测到后，确认来源并点击「导入」。没有检测到时直接正常启动。

来源不对可点击「选择其他路径」，在文件夹选择窗口中选择旧版 `runtime`。选择「暂不导入」或导入失败后仍可正常启动，不会在下次启动时反复询问；失败会显示 GitHub 反馈地址，旧数据保留。

旧安装在其他位置，或已经打开过新版，也可以关闭软件后双击导入工具：Windows 为 `导入旧数据.cmd`（与 `bilikara-desktop.exe` 同一级），macOS 为 `导入旧数据.command`（与 `bilikara-desktop.app` 同一级）。在弹出的文件夹选择窗口中选择旧版 `runtime` 或 `data`；不用编辑脚本或输入命令。

工具也支持 Preview 2 的新版格式：直接复制并校验，保留媒体缓存和设备登记。旧格式则转换歌单、历史和分场记录，媒体需重新缓存，Remote 设备需重新登记。

导入完成后，旧数据会按原文件形式保存为备份（外部来源位于旧位置旁的 `.bilikara-imported-…/data`），完成窗口会显示实际备份位置。点击「打开文件夹」可一次打开提示中的备份或残留位置；确认导入后的记录完整后，可手动删除。点击「完成」则关闭提示。若新版已有数据，工具会另行询问，先完整备份当前数据再替换，两份记录不会合并。

Windows 导入完成后，若 `%APPDATA%\com.bilikara.app\main-window-geometry-v1.json` 存在且有效，会沿用旧版窗口位置、尺寸和最大化状态，保存到软件旁的 `runtime\main-window-geometry-v1.json`。新版已有窗口配置时保留新版；旧配置缺失或无效不会影响导入和启动。原件保留，确认不再使用旧版后可手动删除。

旧格式导入失败时，确认过的旧数据也会移到备份：外部来源保存在新版数据位置旁的 `legacy-backup`，同目录的旧数据保存在导入备份中。失败提示会显示位置，并继续正常启动；之后仍可选择这份备份重新导入。如果文件占用等原因使移动不安全，就保留原件并说明，不强行删除。
