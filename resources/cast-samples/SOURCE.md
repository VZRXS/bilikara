# DLNA test sample B: source and verification

Sample B is the "uniform encoding" column of the DLNA self-test matrix (fix plan §5.2b item 2, §7.4, T8).
It is a pre-encoded clip that uses Kirakara Show's cast encoding parameters. Comparing it with sample A
(passthrough of the original encoding) shows whether a receiver failure comes from the source encoding
parameters or from the delivery mode.

## Content (synthetic, no third-party media)

Every input is generated by FFmpeg's built-in lavfi sources; there is no camera footage, music or
third-party artwork.

- Video: `testsrc2` (moving gradient, rotating line, counters), with a 240×240 magenta block that
  bounces horizontally across the bottom (600 px/s) and a dark top banner showing:
  - the elapsed whole second in very large type (0–19);
  - the presentation time `HH:MM:SS.mmm` and the frame number;
  - the label "bilikara DLNA sample B - synthetic test pattern".
  A frozen clock, a jumping frame number or a stalled block identifies stalls and skips by eye.
- Audio: `aevalsrc`, generated stereo.
  - A continuous tone at −12 dBFS (amplitude 0.25) whose pitch steps every second (330 Hz + 55 Hz × (second mod 8)),
    so gaps and repeats are audible.
  - A 1 kHz, 80 ms beep at the start of each second: left channel on even seconds, right channel on
    odd seconds, so channel swaps or a lost channel are audible.
- Text font: Source Code Pro Bold, SIL Open Font License 1.1 (conda-forge
  `font-ttf-source-code-pro` 2.038). Only rendered glyph pixels are in the video; the font file is not
  distributed.

## Target parameters (Kirakara Show cast profile)

Taken from `Kirakara-Show/apps/show_host/cast/`: the 1080p30 profile at 4,500,000 bit/s
(`cast_session.cpp`), MF H.264 CBR with GOP size set and B-frame count 0
(`mf_d3d11_h264_encoder.cpp:1068-1078`), and AAC 48 kHz stereo at 20000 bytes/s, i.e. 160 kbit/s
(`mf_aac_encoder.h`). Kirakara does not set an H.264 profile explicitly; the plan allows Main or High,
and Main was chosen as the more conservative option.

## Generation command

Run from the output directory with `FFMPEG` pointing at the FFmpeg above and `FONT` at
`SourceCodePro-Bold.ttf` (drive colon escaped for drawtext, e.g. `C\:/.../SourceCodePro-Bold.ttf`):

```bash
FFMPEG=/path/to/ffmpeg FONT='C\:/path/to/SourceCodePro-Bold.ttf' bash generate.sh
```

`generate.sh` in full:

```bash
#!/usr/bin/env bash
# Generates bilikara DLNA test sample B (synthetic, copyright-free) in the current directory.
set -euo pipefail
FFMPEG="${FFMPEG:-ffmpeg}"
# Source Code Pro Bold (SIL OFL 1.1), conda-forge font-ttf-source-code-pro 2.038. ":" must be escaped for drawtext.
FONT="${FONT:?set FONT to SourceCodePro-Bold.ttf, with the drive colon escaped as C\:/...}"
VIDEO_FILTER="[0:v][1:v]overlay=x='abs(mod(t*600\,2*(W-w))-(W-w))':y=H-h-40[bg];\
[bg]drawbox=x=0:y=0:w=iw:h=300:color=black@0.6:t=fill,\
drawtext=fontfile='${FONT}':text='%{eif\:trunc(t)\:d}':fontsize=260:fontcolor=white:x=60:y=20,\
drawtext=fontfile='${FONT}':text='%{pts\:hms}  frame %{eif\:n\:d}':fontsize=64:fontcolor=yellow:x=560:y=70,\
drawtext=fontfile='${FONT}':text='bilikara DLNA sample B - synthetic test pattern':fontsize=40:fontcolor=white:x=560:y=170,\
format=yuv420p[v]"
AUDIO="aevalsrc=exprs='0.25*sin(2*PI*(330+55*mod(floor(t)\,8))*t)+0.35*sin(2*PI*1000*t)*lt(mod(t\,1)\,0.08)*eq(mod(floor(t)\,2)\,0)|0.25*sin(2*PI*(330+55*mod(floor(t)\,8))*t)+0.35*sin(2*PI*1000*t)*lt(mod(t\,1)\,0.08)*eq(mod(floor(t)\,2)\,1)':s=48000:c=stereo:d=20"
"$FFMPEG" -hide_banner -y \
  -f lavfi -i "testsrc2=s=1920x1080:r=30:d=20" \
  -f lavfi -i "color=c=0xFF00FF:s=240x240:r=30:d=20" \
  -f lavfi -i "$AUDIO" \
  -filter_complex "$VIDEO_FILTER" -map "[v]" -map 2:a \
  -c:v libx264 -preset medium -profile:v main -level:v 4.0 -pix_fmt yuv420p -r 30 \
  -b:v 4500k -minrate 4500k -maxrate 4500k -bufsize 2250k \
  -x264-params "keyint=15:min-keyint=15:scenecut=0:open-gop=0:bframes=0:nal-hrd=cbr:force-cfr=1:repeat-headers=1" \
  -c:a aac -profile:a aac_low -b:a 160k -ar 48000 -ac 2 \
  -t 20 -f mpegts sample-b.ts
"$FFMPEG" -hide_banner -y -i sample-b.ts -map 0 -c copy -movflags +faststart -f mp4 sample-b.mp4
```

Video is encoded once into MPEG-TS. The MP4 is a stream-copy remux of that TS (`+faststart`, moov
first), so both containers carry the same encoded pictures and audio.

**Reproducibility.** Rerunning the command yields files with the same parameters, but not
byte-identical files. x264's multi-threaded CBR rate control decides where to insert filler data based
on thread timing. Forcing `threads=1` gives byte-identical reruns but drops HRD filler, letting the
per-GOP bitrate wander between 3.9 and 5.3 Mbit/s. Strict CBR is the property under test, so the
default threading was kept. The SHA-256 values above identify the shipped files; verify a regenerated
clip with the checks below rather than by hash.

## Verification (ffprobe / ffmpeg 7.1.1)

| Check | `sample-b.ts` | `sample-b.mp4` |
| :--- | :--- | :--- |
| Container / duration | mpegts, 20.021 s | mp4 (moov first), 20.032 s |
| Overall bitrate | 4,826,677 bit/s | 4,652,136 bit/s |
| Video codec / profile / level | H.264 Main, level 4.0 | H.264 Main, level 4.0 |
| Resolution / pixel format / frame rate | 1920×1080, yuv420p, 30/1 CFR | same |
| B-frames | `has_b_frames=0`; decode-order PTS strictly increasing | same |
| Frames / keyframes | 600 frames, 40 IDR keyframes | same |
| GOP | every 15 frames = 0.50 s, closed (`scenecut=0`, `open-gop=0`) | same |
| Video bitrate | avg 4490 kbit/s; first GOP 4051, all other 39 GOPs 4501 kbit/s | avg 4491; first 4052, others 4502 |
| Audio | AAC-LC, 48000 Hz, 2 ch stereo, 163,470 bit/s, 19.968 s | AAC-LC, 48000 Hz, stereo, 161,230 bit/s, 20.032 s |
| Audio level | L peak −0.57 dBFS, R peak −4.03 dBFS, both RMS −14.73 dBFS (no clipping) | same stream |

Bitstream checks (`-bsf:v trace_headers` on the TS):

- 40 IDR slices, each preceded by in-band SPS and PPS (41 SPS and 41 PPS including the stream start).
  A receiver can join at any keyframe.
- SPS VUI: `nal_hrd_parameters_present_flag=1`, `cbr_flag=1`, `max_num_reorder_frames=0`.
- 310 filler-data NAL units keep the bitrate constant; 600 access-unit delimiters.
- Decoded video is identical in both containers (`-f md5`:
  `dd1d7a30af571f8bf7f04dd5077a7497` for both). The audio elementary streams are identical (ADTS
  SHA-256 prefix `bf28b41ed01ea23f` for both).

Visual spot checks at 3.5 s, 7.5 s and 12.2 s showed the expected second counter, timecode and frame
number (for example 7.5 s shows frame 225), the label, and the magenta block at a different position
each time.
